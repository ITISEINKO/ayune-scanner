# LBY model workspace

`/drafter` contains the shared import form and saved models with Models/Cari/Profile navigation. Admins enter `/admin/import-3d` through **Kelola model LBY** on their profile and retain admin navigation. Both pages use `LbyImportPage` and the same import API/converter. `/drafter/profile` contains drafter account details and logout. Import-enabled members land on `/drafter` after login or session refresh. No ClickUp project selection or hierarchy lookup is required.

`/cari-lokasi` provides read-only panel search for active members and import-authorized drafters. Camera/keyboard scanning navigates to `?barcode=<exact serial>`, and the server reads the existing active-model serial index and bundled snapshots directly. No selected project, ClickUp task lookup, or status update is needed. Results reuse the immersive location viewer with panel details and a return-to-scan link. Current database access is checked on every page request; missing/ambiguous locations show a recoverable message. The member layout uses the signed session's `can_import_lby` capability for the navigation workspace, so drafters retain Models/Cari/Profile on the shared search page and ordinary members retain Projects/Cari/History/Profile. This display hint does not replace the fresh database authorization check.

ADMIN has built-in import access. MEMBER and SUPER_ADMIN accounts can receive **Drafter: model LBY** from Settings > user > Akses halaman. This capability is stored in `ppic_permissions.can_import_lby` (0 or 1), alongside the existing role and scan permissions. It permits import, draft preview, activation and rollback, including for users with no scan access. SUPER_ADMIN and MEMBER accounts without the flag remain excluded. Granting or revoking LBY access does not modify roles, scan statuses or the scan active flag. `active=0` disables member scan authorization while `can_import_lby=1` still permits the drafter workspace. A granted SUPER_ADMIN retains the admin landing page and gains the model-management entry on their profile.

The workspace, preview reader and import API check the current database capability. POST and PATCH recheck it before saving/activating; revocation during a download blocks the candidate save and releases its lease. Signed MEMBER sessions can carry `can_import_lby: true` without scan statuses, but this claim alone cannot authorize imports or previews. No existing role CHECK constraint is changed.

## User flow

1. On `/drafter` or `/admin/import-3d`, paste the complete LBY `cadVisitor` share URL and click **Import model**. The page disables duplicate submission while it waits. No progress percentage is invented.
2. The list shows one card per model with its name, current saved-content date, panel/room counts and **Update model**. Updating preloads its saved share link into the existing form, lets the user replace an expired link, and submits the existing project key to retain order isolation. **Batal update** returns to a new-model import.
3. Success stages a candidate inside the model card. **Preview pembaruan** opens a pinned preview in a separate tab and prepares a confirmation in the original tab. **Gunakan model ini** changes the active reference only after confirmation; cancelling leaves the current model unchanged.
4. **Versi sebelumnya** is collapsed by default. It contains numbered history and pinned previews; selecting an inactive history preview uses the same confirmation flow for recovery. Bundled fallback restoration remains available there with explicit confirmation. Identical viewer data reuses the original revision/import time. No saved revision is deleted.
5. Invalid/expired links, vendor errors, failed mapping/checksums, oversize data and request conflicts display an error. Failed imports do not replace the active model. On a lost response or timeout, reload the page to check saved candidates before retrying.

New sources use `lby-<orderId>` as their storage key. A matching existing import or bundled order keeps its previous key and revision history. Existing order associations cannot be replaced with a different order. Concurrent activation uses the expected active revision; stale attempts return a conflict instead of silently overwriting another admin.

## Persistence and reads

The existing `TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN` connection is reused. No Blob account, new package, production secret, cron, or worker service is required. The application lazily creates three model-storage tables:

- `ppic_panel_location_project`: project/order identity, active revision and a fenced 330-second import lease.
- `ppic_panel_location_revision`: immutable sanitized snapshot/mapping as gzip BLOBs, manifest/count metadata and importing actor. SHA-256 checks are preserved. No share tokens, signed vendor URLs, full raw CAD, prices or images are saved in revision payloads.
- `ppic_lby_source_link`: the latest successfully imported, validated LBY share URL per model, including its original share token. This private management data is separate from snapshots and returned only through the import-authorized management API. Re-importing identical geometry refreshes this link without adding a version or activating anything. Old imports have no recoverable source URL until re-imported. Links retain their vendor expiry; no tokens are generated or extended. Do not log or commit real links.
- `ppic_panel_location_barcode`: exact serial-to-revision index, joined against active references so candidates and superseded revisions do not participate. Existing active snapshots are backfilled on initialization; activation also indexes older candidates.

LBY authorization uses the existing `ppic_permissions` table. The `can_import_lby INTEGER NOT NULL DEFAULT 0 CHECK (can_import_lby IN (0, 1))` column defaults to denied for non-ADMIN users. Import-only users have a MEMBER row with scan `active=0`; the legacy required `allowed_status` field does not authorize scanning while inactive.

Before running this application revision against an older database, run `node scripts/consolidate-lby-permissions.cjs`. The migration verifies a private backup of both permission tables, adds the column, copies existing flags (including import-only accounts without a permission row), checks roles/statuses and database integrity, then drops `ppic_lby_import_permission` in the same transaction. Failures roll back; reruns are idempotent. The optional `--grant-user CLICKUP_USER_ID` enables the flag for one existing account without changing its role or scan access. Deploy the updated application together with this migration; older application code must not recreate or write the legacy permission table.

`getPanelLocation` resolves exact board/serial numbers across active imports and available bundled snapshots; leading zeroes remain intact. `/panel-location?barcode=<serial>` works without a project parameter. Explicit revision previews require a source key and current LBY import access. Multiple active matches report `LOCATION_AMBIGUOUS` instead of selecting a model. Manual status lookup retains its ClickUp serial/status lookup but no longer walks parent tasks to find a location. Location conflicts leave status editing available.

Viewer panels include optional panelName and doorOpenType (left, right, up, bottom). Import preserves the supported source CAD opening direction in both sanitized snapshots and mappings; absent, none and unsupported directions are omitted. New import content creates a new immutable candidate; review and activate it to replace the active version. Existing revisions are never rewritten. Reader enrichment joins saved names/details by exact barcode; older explicit Chinese left/right door-board names supply a direction when the field is absent. Other unknown directions remain closed, with the Open/Close control disabled if no supported doors exist.

The right toolbar contains Open/Close doors, Hide/Show doors and Reset. Opening reveals hidden doors, swings them 90 degrees around their source box hinge edge over 450ms and stops scheduling animation frames when finished. Reduced-motion users get the end position directly. Reset cancels animation and restores closed/visible doors. This mirrors the supported hinged-door behavior of LBY's animation switch; drawer sliding and grouped hardware motion are not included. Full hinge-circle bounds keep the camera stable throughout the swing. Door hiding uses explicit opening metadata or panel names, never room names; unknown panels and the searched panel stay visible. Pull-out moves only the searched panel along its shortest box edge with an original-position outline and guide line. These controls are location aids, not a physical assembly sequence. Wheel/trackpad, pinch and keyboard +/- zoom; drag or keyboard arrows rotate. No rotation/zoom buttons remain.

Bundled catalog entries retain a mapping path; online reads reuse checksum-verified saved mappings. Only sanitized panel details reach the client. Existing revision payloads/checksums stay unchanged until a new candidate is explicitly imported and activated.

`GET /api/panel/manual?serial_number=<serial>` also returns a known active LBY location when ClickUp returns no matching task: `data.task_id` and `data.status` are null, and the UI displays the location with status editing disabled. No task or status is invented. A serial absent from both sources still returns 404; ClickUp errors and duplicate task matches retain their error responses. An ambiguous/unavailable location without a ClickUp task returns an explicit error instead of a false not-found result.

Online imports never write to the deployed repository or `/tmp`. Both viewers use the saved DB active revision first; projects without one retain their bundled snapshot. Immutable revision payloads are cached, while the current active pointer is read from the DB on each request. Only the selected room is sent to the browser. Previewing an inactive revision requires current LBY import access. Import-authorized users can also restore a project's bundled model from the models page when one exists.

The CLI remains available and shares the same download/validation/mapping function. Its catalog activation changes the bundled fallback, not an already-active DB revision. Online DB activation requires no model rebuild/redeploy after the feature itself has been deployed.

## Vercel Hobby configuration and limits

`vercel.json` enables Fluid Compute; only `/api/admin/panel-locations` declares `maxDuration = 300`. The shared importer uses one 240-second download deadline across its requests, with panel/model lookups in parallel. The browser allows 290 seconds for the response. Waiting is bounded, and a function terminated by Vercel leaves a lease that expires automatically. No work relies on continuing after a response.

The Node runtime is pinned to `22.x` in `package.json` because ZIP validation uses native `node:zlib.crc32`. Limits: request body 24 KiB; pasted URL 20,000 characters; remote response/archive JSON 64 MiB; online sanitized viewer JSON 1 MiB; mapping JSON 8 MiB; combined compressed DB payload 1 MiB. Oversized online models must use the CLI or a separately designed storage path. API responses contain small metadata; preview/view responses contain only room geometry.

Checked 2026-10-28 against [Vercel function limits](https://vercel.com/docs/functions/limitations) and [Fluid configuration](https://vercel.com/docs/project-configuration/vercel-json#fluid): Hobby with Fluid Compute supports up to 300 seconds, and function request/response bodies are capped at 4.5 MB. These settings do not establish actual production configuration, available quotas or guaranteed vendor latency.

## API contract

`GET /api/admin/panel-locations` returns `{ ok: true, states }` for saved imports. The optional `?project=<storage key>` retains the scoped `{ ok: true, state }` response. Each state includes `projectKey`, `activeRevision`, `bundledVersion`, saved `versions`, and optional `sourceUrl` (the model's latest saved LBY share link). Each version includes project/order/name, full revision, short version, import time, checksums, panel/room counts and a sample barcode. No geometry is returned here. Source links are available only to users with current import access; ordinary member location and version responses do not include them. The Models cards show Preview and Buka di LBYERP separately; older imports show a disabled Link belum tersimpan button with a re-import explanation.

`POST /api/admin/panel-locations` accepts `{ "url": "FULL_SHARE_URL" }`, derives the storage key from the order identity, returns `{ ok: true, candidate, state }`, and stages only. **Update model** also sends the existing `project` key to preserve order isolation. The source URL must be passed in the JSON body, not an endpoint query parameter or log.

The `/drafter` form requests `Accept: application/x-ndjson` for import progress. After access/body/link/lease validation, the response is a newline-delimited stream of `{ stage: "downloading" | "panels" | "rooms" | "saving" }` followed by the same final success object, or `{ ok: false, error }`. Stages come from actual server work: fetching model data, parsing/joining panel records, building room geometry and saving the candidate. They are phase markers, not downloaded-byte percentages. Errors before streaming retain their ordinary HTTP status/JSON response; errors after headers use a terminal error event in the HTTP 200 stream. A missing terminal event is an incomplete response, never success. Requests without this Accept header keep the existing JSON/status contract.

While importing, the form becomes a four-step card with an active spinner, completed checks, elapsed seconds and a stage progress bar. Paste uses an icon with accessible name `Tempel`. `Batalkan` aborts the browser request; the server combines disconnect/cancel with its existing deadline, cancels upstream HTTP and checks abort before saving. The import lease is released in the worker's `finally`. Cancellation is disabled during the final save, which is not an undo operation; a DB write already in flight can still complete. Active revisions remain independent and require explicit activation. Navigating away aborts a pending import. Hosting/proxy buffering and disconnect propagation still need deployment verification.

`PATCH /api/admin/panel-locations` accepts `{ "project": "PROJECT_ID", "revision": "FULL_SHA256", "expectedActiveRevision": null }`. Send the current `activeRevision` instead of null on subsequent changes. A null `revision` restores a bundled model, only when that project has one. Success returns `{ ok: true, state }`.

Errors return `{ ok: false, error }`: 401 `UNAUTHORIZED`; 403 `LBY_IMPORT_REQUIRED`; 400 invalid request/project/link or `LINK_EXPIRED`; 409 `ORDER_MISMATCH`, `IMPORT_BUSY`, `IMPORT_CONFLICT`; 413 `REQUEST_TOO_LARGE` or `MODEL_TOO_LARGE`; 422 `LBY_NO_PANEL_DATA`; 429 `RATE_LIMITED`; 504 `IMPORT_TIMEOUT`; 502 `IMPORT_FAILED`. Candidate lookup returns 404 `REVISION_NOT_FOUND`. Original vendor exception text is not exposed.

`LBY_NO_PANEL_DATA` means the LBY panel lookup succeeded with an empty array. A CAD model may still be viewable in LBY, but there are no production serials to join to its geometry for barcode lookup. CAD board numbers (`roomPlankIdx`) are not scan serials and are never substituted for them. No candidate is saved, the existing active model is retained, and the lease is released so import can be retried after panel/serial data is available from LBY.

Member administration retains its existing admin-only endpoint. `GET /api/panel/members` returns `lbyImporters: Record<string, boolean>` from the permission column. `POST /api/panel/members` accepts `{ user_id, can_import_lby: boolean }` as one update operation, mutually exclusive with role or allowed_status updates. Targets must be channel members; a missing permission row is created as an inactive MEMBER. Explicit SUPER_ADMIN grants are supported; ADMIN retains built-in access. Existing highest-role protections and both realtime notifications remain. LBY updates publish `canImportLby` without replacing cached scan permissions. The Settings form submits only changed permissions.

## Readable versions and outdated views

Saved revisions expose `versionNumber`, displayed as V1, V2, V3 per model. `ppic_panel_location_revision.version_number` is added lazily for existing databases; old rows are numbered in their original insertion order, without changing their metadata or compressed snapshots. A unique `(project_id, version_number)` index prevents duplicate numbers. New candidates receive the next number inside the existing fenced write transaction; identical content reuses its original number. Bundled models reserve V1, so their first online candidate is V2. There is no revision deletion flow.

The models page groups revisions by project and shows the active saved model, or the latest candidate when none is active. A latest candidate different from the active revision appears as an update ready for review. A rollback can leave V1 active while V2 remains available as an update. Version numbers appear only inside collapsed history; the main list counts models. Hashes stay internal for content identity, checksums and pinned preview URLs. Bundled model counts are unavailable in the list response, so a card using the bundled fallback explicitly labels displayed candidate counts as update counts.

Normal searches continue to read only the active revision. The shared viewer displays its version number, checks saved active-version metadata on mount and every 30 seconds while visible, and rechecks on visibility/reconnect. Hidden tabs pause interval checks. If the active revision changes, the viewer keeps its displayed geometry and shows the displayed/active numbers with **Muat versi aktif**. That action reloads normal member/admin views, or leaves an explicit pinned preview for the normal active lookup. Explicit previews are labeled **Preview versi Vn**; a candidate with no active model is identified as such. Failed checks show a retry control without claiming that the loaded version is current.

`GET /api/panel/location-version?project=PROJECT_KEY` returns `{ active: { version: "INTERNAL_CONTENT_ID", versionNumber: 2 } }`, or `{ active: null }` when no active/bundled model exists. It checks the signed session, token presence and current member/admin/import capability, validates exactly one project key, and returns `private, no-store`. Errors are 401 `UNAUTHORIZED`, 403 `FORBIDDEN`, 400 `INVALID_PROJECT`, or 502 `LOCATION_UNAVAILABLE`. After one-time schema initialization, the check reads permission and version metadata only; it does not download geometry or call ClickUp/LBY.

## Local verification

```powershell
npm.cmd run build
postman simulation run tests/lby-online.sim.yaml --port 4914 --output ndjson --no-history
# In another terminal:
node tests/lby-online.cjs
node tests/panel-location.cjs
```

The synthetic fixture waits 21 seconds for its archive to prove the dialog does not time out at 10–20 seconds. Checks cover ADMIN-only controls/API, compressed DB writes, candidate preview, active member reads, activation/rollback, idempotency, fenced import leases, stale activation, failures retaining active data and secret exclusion. `tests/lby-import.cjs` separately checks the shared total-deadline abort and CLI behavior against its port-4913 simulation. No production credentials, live import, deployment or physical device is exercised by these tests.
