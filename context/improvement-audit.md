# Improvement audit

## Method

- **Confirmed:** Findings are static evidence from the named source files only; no production request, task update, Turso query, webhook delivery, or deployment setting was changed.
- **Confirmed:** Severity reflects potential user/data effect in the shown code, not observed incident frequency.

## Recommended first improvement

- **Confirmed:** The first safe change is observability, not a new cache or automatic retry: add redacted timing/error instrumentation around project-list, serial-cache preload, dashboard fetch/transform, Turso reads/writes, and scan write stages.
- **Inferred:** Those measurements decide whether the next narrow change should be dashboard freshness, full-list avoidance, or a targeted repair record for partial scan writes.
- **Unverified:** No source evidence establishes that Redis, a new database, a global cache, or retries are currently needed.
